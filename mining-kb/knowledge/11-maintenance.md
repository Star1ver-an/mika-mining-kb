# 知识库维护规则

## 触发场景
用户把公众号文章正文（或链接+正文）发给助手，要求「纳入知识库」「更新知识库」「记住这篇」。

## 处理步骤（固定）
1. **确认完整性**：正文是否从标题到结尾完整；若只有链接或摘要，先说明只拿到摘要，不能冒充全文。
2. **抽取元数据**：标题、公众号、发布时间、原文链接、正文字数。
3. **判断主题**：AI找矿 / 地质灾害 / 深地科学 / 矿产战略 / 矿山机器人 / 政策 / 世界模型与物理AI / 数据资源 / 地质基础。
4. **写卡片**：归到对应 `kb-*` 卡片下，追加一节：
   ```
   ### N. 《标题》（公众号，日期）
   [原文链接](url)
   > 一句话结论
   正文要点（保留关键数字、方法名、结论原句，不改写原意）
   ```
5. **更新索引**：在卡片开头的「收录」列表里加一行。
6. **回执**：告诉用户落在哪张卡、新增多少字、主题是什么。

## 硬规则
- 不改写原文事实性内容；提炼时标注「原文要点」。
- 图片型文章要明确说「文字通道覆盖不到图内信息」。
- 二手转述标为 B 级证据。
- 没有拿到全文时，绝不编造引用。

## 归档位置（App 内）
知识卡是 Kelivo 技能，位于 `skills/<技能id>/SKILL.md`，用 read_file 读取。
